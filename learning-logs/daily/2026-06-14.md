# 2026-06-14 学习日志

今天深入研究了李宏毅机器学习 HW03（food-11 食物图片分类），从 baseline 跑通到多次迭代优化，覆盖了数据增强、模型架构、训练策略、半监督学习和设备兼容等多个方面。

## 今天做了什么

### 1. 问题排查与 Bug 修复

#### lambda 序列化错误
- `DatasetFolder` 使用 `lambda x: Image.open(x)` 作为 loader
- 当 `num_workers > 0` 时，多进程无法 pickle lambda 函数
- **修复**：改用 `Image.open` 普通函数

#### ResNet18 分类头未替换
- `torchvision.models.resnet18()` 默认输出 1000 类，food-11 只有 11 类
- 直接训练会报 `RuntimeError: mat1 and mat2 shapes cannot be multiplied`
- **修复**：`model.fc = nn.Linear(model.fc.in_features, 11)`

#### 设备不匹配
- 先 `model.to(device)` 再替换 `model.fc`，新层默认在 CPU
- 导致 `RuntimeError: Expected all tensors to be on the same device`
- **修复**：先替换 fc 层，再统一 `.to(device)`

#### 训练/验证 Normalize 不一致
- `train_tfm` 加了 `Normalize`，`test_tfm` 没加
- 训练时输入减去均值，验证时没减，分布完全不同
- 结果：验证 acc 从 40% 掉到 14%（严重过拟合假象）
- **修复**：test_tfm 必须加相同的 Normalize

### 2. 数据增强策略演进

| 版本 | train_tfm 内容 | 效果 |
|------|---------------|------|
| v1 | Resize + ToTensor | baseline ~45% |
| v2 | + RandomCrop + Flip + ColorJitter + Normalize | 改善明显 |
| v3 | + RandomErasing + AutoAugment | 当前版本 |
| v4 | RandomResizedCrop 替代 Resize+Crop | 更灵活 |

**关键认识**：
- `Normalize` 必须在训练和测试保持一致，否则模型看到的数据分布完全不同
- `AutoAugment(ImageNet)` 自动选择最优增强策略，比手动组合更鲁棒
- `RandomResizedCrop` 比 `Resize + RandomCrop` 更灵活（缩放和裁剪同时进行）
- `RandomErasing` 通过遮挡强迫模型关注局部特征，防过拟合
- **数据增强太强模型无法训练下去，要掌握好度！！！**

### 3. 模型架构优化

#### 原始 3 层 CNN
```
Conv(3→64) → BN → ReLU → Pool →
Conv(64→128) → BN → ReLU → Pool →
Conv(128→256) → BN → ReLU → Pool →
FC(256*8*8→256→11)
```
- 参数量 ~4.5M，但容量不足

#### 5 层 CNN + SE 模块
```
Conv(3→64) → BN → ReLU → SE → Pool →
Conv(64→128) → BN → ReLU → SE → Pool →
Conv(128→256) → BN → ReLU → SE → Pool →
Conv(256→512) → BN → ReLU → SE → Pool →
Conv(512→512) → BN → ReLU → Pool →
FC(512*4*4→512→11)
```
- 参数量 ~5.5M
- **SE Block（Squeeze-and-Excitation）**：自动学习通道注意力
  - 对每个通道计算全局均值 → 两层 FC（降维再升维）→ Sigmoid 得到权重
  - 乘以原特征图，让模型自动关注重要通道（如"金黄色"通道加权，"背景灰色"通道压下去）
- 加了 `padding=1` 保留空间信息（原来 padding=0 导致特征图越压越小）
- 通道数从 1024 降到 512（1024 过拟合严重）

#### ResNet18 的局限
- ResNet18 是为 ImageNet 224×224 设计，前几层 stride=2 的 7×7 大卷积核 + maxpool
- 对 128×128 输入降采样太猛，第一层就把分辨率从 128 砍到 32
- 参数量 11M，对 food-11（仅 11 类）过大
- **结论**：轻量 CNN + SE 模块更适合此任务

### 4. 训练策略优化

| 参数 | 原始值 | 优化后 | 原因 |
|------|--------|--------|------|
| 学习率 | 0.0001 | 0.003 | 加快收敛 |
| 优化器 | Adam | AdamW | 更好的权重衰减 |
| 学习率调度 | 无 | CosineAnnealingLR | 从 0.003 逐步降到接近 0 |
| Early Stopping | 无 | patience=15 | 连续 15 epoch 不提升则停止 |
| 最佳模型保存 | 无 | 每个 epoch 保存最佳 | 训练结束后加载最佳模型 |

#### 触发条件
```python

```
- `do_semi = True`：开关
- `best_acc > 0.7`：验证集超过 70% 才开始（模型足够准才能生成可靠伪标签）

- `threshold=0.9`：只保留模型非常自信的样本，避免噪声标签

## 收获

- **数据增强的核心原则**：训练和测试的预处理必须一致（尤其是 Normalize）
- **模型架构不是越大越好**：参数量要与任务复杂度匹配，food-11 只需 ~5M 参数
- **SE 模块的威力**：通道注意力让模型自动聚焦关键特征，比单纯增加通道数更有效
- **半监督学习的时机**：模型足够准（acc > 0.7）再开始，否则伪标签噪声会拖垮模型
- **Early stopping 的 patience**：太激进会错过后期提升，太宽松会浪费时间
